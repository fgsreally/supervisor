# 移动端设计语言

## 字号与缩放

界面采用移动优先的 `rem` 尺寸体系。用户在设置页选择字号后，偏好保存到
`localStorage`，同时作用于电脑端和移动端：

| 档位   | 移动端根字号 | 电脑端根字号 |
| ------ | -----------: | -----------: |
| 紧凑   |         15px |         12px |
| 标准   |         16px |         13px |
| 大字号 |         18px |         16px |

字体、图标、触控目标、头像、气泡和主要间距使用 `rem`，确保放大后仍维持合理比例。
仅 1px 分隔线、阴影等不应随字号变化的视觉细节，以及拖拽宽度等必须参与像素计算的
交互几何可保留 `px`。

## 微信风格依据

`wechat` 风格以微信官方设计团队维护的 [WeUI](https://github.com/Tencent/weui) 为优先依据。字体使用官方 `system-ui, -apple-system, "Helvetica Neue", sans-serif` 系统字体栈，并补充官方列出的中文回退字体。亮色前景层级使用黑色 90% / 55% / 30%，背景使用 `#ededed` / `#f7f7f7` / `#ffffff`，品牌绿使用 `#07c160`，用户气泡使用 `#95ec69`，链接使用 `#576b95`。暗色模式采用官方 WeUI 暗色变量。

官方参考：[字体变量](https://github.com/Tencent/weui/blob/master/src/style/base/variable/global.less)、[亮色主题](https://github.com/Tencent/weui/blob/master/src/style/base/theme/vars/light.less)、[暗色主题](https://github.com/Tencent/weui/blob/master/src/style/base/theme/vars/dark.less)、[Article](https://github.com/Tencent/weui/blob/master/src/style/widget/weui-page/weui-article.less)、[Link](https://github.com/Tencent/weui/blob/master/src/style/widget/weui-text/weui-link.less)。WeUI 没有定义的技术 Markdown 与桌面布局属于本项目扩展，必须从官方灰阶、背景、分隔线和语义色推导。

微信主题的 Markdown 扩展使用官方绿色族建立识别：Brand 用于标题标记和关键字，TextGreen 用于行内代码与字符串，Green 深色级别用于数字，LightGreen 用于暗色代码高亮。标题正文仍使用官方主前景色，真实链接仍使用官方 Link 色。引用、表头和代码边框只使用对应绿色的低透明度背景，不引入 WeUI 色板之外的强调色。

本项目亮色布局统一使用“白色画布、灰色内容块”：页面、聊天、列表和设置底色使用 `#ffffff`；搜索框、卡片和输入控件使用 `#f7f7f7`；助手气泡及更强的块层级使用 `#ededed`。这是基于 WeUI 官方 BG-2 / BG-1 / BG-0 色阶针对本项目信息架构确定的映射，不得在页面中反向使用。

桌面端按照微信 PC 的紧凑比例使用 13px 根字号和 12px 聊天正文；移动端根字号使用 16px。PC 的固定像素 Header、列表宽度、头像、气泡和工具按钮也必须使用桌面密度覆盖，不能只依赖根字号缩放。主题不得改变 PC 既有布局，聊天字号由各主题单独控制。

本规范主要约束宽度不超过 767px 的移动端界面，PC 继续使用现有布局和交互。视觉风格是全端偏好：用户可在设置页选择 `wechat` 或 `clarity`，选择保存在浏览器 localStorage 中，不进入 URL；两套风格都支持亮色和暗色模式。

## 设计目标

- 首屏先回答“这是什么、当前怎样、下一步做什么”。
- 一个页面只设置一个视觉主操作；技术信息和低频配置进入二级页。
- 同一种控件只保留一种结构和状态语言，页面不得自行发明按钮、输入框和弹层样式。
- 触控目标不小于 44×44px，文字和背景至少满足 WCAG AA。
- 聊天是高密度工作区，不盲目套用大字号和宽松卡片。

## 风格与颜色模式

`data-app-style` 决定全端视觉风格，`data-theme` 决定亮暗模式，二者相互独立。

| 项目         | WeChat     | Clarity    |
| ------------ | ---------- | ---------- |
| 页面标题     | 17px / 600 | 24px / 650 |
| 正文         | 16px       | 16px       |
| 辅助文字     | 13px       | 13px       |
| 状态文字     | 11–12px    | 12px       |
| 单行列表     | 56px       | 60px       |
| 双行列表     | 64px       | 68px       |
| 卡片圆角     | 8px        | 12px       |
| 功能图标容器 | 32px       | 34px       |

微信亮色使用 `#ededed` / `#f7f7f7` / `#ffffff` 背景层级、`rgba(0,0,0,.9)` 主文字、`rgba(0,0,0,.55)` 辅助文字、`rgba(0,0,0,.3)` 弱文字、`#576b95` 链接和 `#07c160` 品牌色。暗色模式直接采用官方 WeUI 暗色变量，不自行反转颜色。

基础间距只能从 `4、8、12、16、20、24px` 中选择。布局可以组合这些间距，不使用难以复用的零散数值。

## 信息与可读性

- 列表行只展示识别和决策需要的信息：名称、简短用途、关键状态。
- 路径、内部 ID、环境变量、Base URL、Context、原始日志等进入“高级与诊断”。
- 必须出现英文术语时附带用途说明，例如“Skills：可复用的专业能力”。
- 长说明在列表中最多两行；完整文本进入详情页面。
- 禁止通过一排没有解释的标签表达复杂配置。

## 图标与对齐

- 页面右边距、操作按钮点击区域和图标尺寸统一使用 `--m-page-inline`、`--m-action-hit-size`、`--m-action-icon-size`。
- Header、列表尾部和底栏按钮使用同一个 44px 操作网格。右侧单按钮的中心必须处于 `视口右侧 - 页面边距 - 22px`。
- SVG 使用 24×24 viewBox、圆角端点和圆角连接；视觉尺寸默认 20px。
- 禁止用负 margin 或 `translate` 修正普通图标。光学偏差应在 SVG viewBox 或路径中解决。
- 不熟悉的业务动作不能直接套用含义相近但语义错误的通用图标。外部会话导入使用 Lucide `MessageSquareReply`，以对话框和曲线箭头表达语义，不使用下载托盘。

## 交互承载方式

### Popover

用于依附控件的简短说明、状态详情或不超过 5 个短选项。点击外部或 Escape 关闭，并把焦点还给触发按钮。不得承载危险确认、长表单或必须完成的任务。

### Bottom Sheet

用于列表项“更多”、上下文操作和短动作集合。危险操作与普通操作分区，取消按钮独立。内容需要持续浏览时改用新页面。

### Dialog

用于阻断信息、危险确认，或不超过 3 个短字段的轻量修改。必须包含标题、取消路径、焦点锁定、滚动锁定和系统返回处理。长文本、多组配置、文件树和多步骤流程必须使用新页面。

### Message

用于操作开始、成功、失败或完成等无需立即决策的反馈。成功提示短暂显示；失败提示说明影响和可执行的下一步。Message 不代替确认框或表单校验。

### 新页面

用于超过 3 个字段、长文本、资源浏览、多步骤操作或需要 URL/返回历史的内容。保存后返回来源页面并恢复列表位置。

## Loading

| 场景                   | 反馈                               |
| ---------------------- | ---------------------------------- |
| 页面首次读取           | 与最终结构一致的 Skeleton          |
| 按钮保存或创建         | 按钮自身 loading，禁止重复提交     |
| 列表逐项操作           | 对应行使用 `UiListStatus`          |
| 列表选择后读取详情     | 选中行轻量状态 + 详情局部 Skeleton |
| 快捷键、拖放、自动提交 | `withUiBusy`                       |
| 后台刷新               | 保留已有内容，仅显示轻量刷新状态   |

## 动画

- 按压反馈：100–140ms。
- Popover 和 Message：140–180ms。
- Dialog、Sheet 和页面切换：200–280ms。
- 动画只解释状态、层级和空间变化。除 loading 外不得无限循环。
- `prefers-reduced-motion: reduce` 下关闭非必要动画。

## 聊天高密度规则

- 消息区左右边距 6px；相邻消息组间距 4–6px。
- 助手头像 24px、头像与内容间距 4px；用户头像在手机端隐藏。
- 助手内容使用头像之外的全部宽度；用户气泡最大使用约 96% 可用宽度。
- 气泡内边距 8px 10px，正文 14px，行高 1.5。
- 工具调用默认只展示一行摘要、状态和关键结果；原始参数和完整输出按需展开。
- Ask、审批、错误和等待用户输入属于关键状态，必须完整展示。
- 时间、耗时和原始模型信息使用弱层级，不得挤压正文。
- 代码块使用完整内容宽度并允许横向滚动。

## 组件使用约束

- 页面必须使用 `MobileButton`、`MobileIconButton`、`MobileField`、`MobileInput`、`MobileTextarea`、`MobileSelect`、`MobileSwitch`、`MobileListRow` 等基础组件。
- 组件输出稳定的 `.m-*` 类名，视觉统一由移动 CSS 控制。
- 移动页面不得新增硬编码颜色、字号、圆角或阴影；确需新增语义时先补 token。
- 写操作继续使用 `showUiMessage`、`requestUiConfirm`、`withUiBusy` 和 `UiListStatus`，不创建第二套业务反馈 API。
