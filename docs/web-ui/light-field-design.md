# 光场控件设计

本文总结 Supervisor Web UI 中局部光场控件的设计与实现约定。这里的“光场”是由控件状态和邻接规则驱动的视觉反馈，不是在页面中放置一个真实、自由移动的光源。

## 设计目标

光场反馈用于表达一个控件正在被指向或按下，以及这次交互对附近控件产生的空间关联。它应满足以下原则：

- 默认状态中性、均匀，不暗示任何固定光源方向。
- 主控件、近邻控件和远邻控件具有清楚但连续的光照层级。
- 光只存在于控件材质内部，不得在控件间隙形成可见光球。
- hover、按压和释放严格跟随输入生命周期，不使用脱离交互的延迟残留。
- 方向、强度和范围来自确定规则，确保相同布局下的反馈稳定可预测。

## 三种视觉状态

### 默认态

默认态是无光场影响的玻璃球：中心近黑，向四周均匀过渡到灰色边缘。

- 使用以 `50% 50%` 为圆心的同心径向渐变。
- 四周边缘亮度必须一致。
- 禁止使用纵向渐变、偏心高光或上下不对称的内阴影。
- 默认态只表达材质，不表达光源。

示意实现：

```css
.light-field-key {
  border: 1px solid rgb(255 255 255 / 16%);
  border-radius: 50%;
  background: radial-gradient(
    circle at 50% 50%,
    rgb(2 2 4 / 98%) 0%,
    rgb(7 7 10 / 96%) 42%,
    rgb(22 22 27 / 94%) 68%,
    rgb(68 69 76 / 90%) 100%
  );
  box-shadow:
    inset 0 0 12px rgb(255 255 255 / 10%),
    inset 0 0 2px rgb(255 255 255 / 18%);
}
```

### 主光态

主光态用于当前 hover 或正在按下的控件。它不是一个纯白圆，而是保留深灰中心、由内向外逐渐变亮，并在外缘形成较厚的白色玻璃高光。

- 中心仍需保留灰黑层次，避免扁平化。
- 白色集中在外圈，轮廓比默认态更清楚。
- 外部辉光应克制，不得形成脱离控件的光团。
- 按压时可以轻微缩小，但不改变控件布局。

### 邻近受光态

主光控件附近的控件按距离分为两级：

- 一级近邻：与主光控件水平或垂直相邻，接受较强光照。
- 二级近邻：与主光控件斜向相邻，接受较弱散射。
- 更远控件：保持默认态。

邻近控件的亮面必须朝向主光控件。例如中心键被激活时，上方按钮的下缘变亮，左侧按钮的右缘变亮。可以将按钮位置映射为二维坐标，并由坐标差计算高光圆心：

```ts
const dx = Math.sign(source.x - target.x);
const dy = Math.sign(source.y - target.y);

const style = {
  "--light-x": `${50 + dx * 42}%`,
  "--light-y": `${50 + dy * 42}%`,
};
```

然后用按钮内部的径向渐变消费这两个变量。高光层必须被按钮的圆形裁切，不能绘制在整个控件组背后。

## 交互状态机

光场状态由输入状态决定：

```text
无交互       -> 所有按钮为默认态
pointerenter -> 当前按钮为主光态，邻居进入受光态
pointerdown  -> 按压按钮优先成为主光态
pointerup    -> 清除按压态；若仍处于 hover，则恢复 hover 光场
pointerleave -> 当前按钮及其邻居立即恢复默认态
pointercancel -> 清除全部指针光场状态
```

键盘输入遵循相同规则：`keydown` 进入主光态，`keyup` 立即退出。忽略重复 `keydown`，避免长按重复提交。

触摸设备不应模拟持久 hover。只有鼠标或支持悬停的指针进入时才记录 hover，触摸仅使用 `pointerdown`、`pointerup` 和 `pointercancel`。

## 实现约束

- 不使用 `:focus-visible` 表示光场状态。焦点是无障碍导航状态，应使用独立轮廓。
- 不使用 `click` 启动按压光效。`click` 发生在释放之后，无法表达“按住期间”。
- 不用定时器让按压光效在释放后残留。
- 不在控件组伪元素中绘制移动白色光球。
- 不为每个按钮写死一个固定高光方向；方向应由主光控件与目标控件的相对位置决定。
- 不因 `disabled` 临时状态改变玻璃球亮度，否则自动提交期间会产生视觉闪烁。
- `prefers-reduced-motion: reduce` 下应移除非必要过渡，但保留状态差异。

## 常见错误

### 默认态带固定方向光

症状是所有按钮始终下方更亮或一侧更亮。原因通常是默认样式使用了纵向渐变、偏心径向渐变或不对称内阴影。默认材质应改为同心径向渐变。

### 按下后变成纯白圆

这会丢失玻璃材质的厚度。主光态应保留暗色中心，把白色安排在中外圈和边缘，而不是直接设置半透明白色背景。

### 控件之间出现光球

这通常来自控件组背后的模糊白色伪元素。局部光场不是物理光照模拟，所有高光都应在按钮自身的裁切区域内渲染。

### 松开后光效仍存在

不要用 `click` 或延迟定时器维护按压态。按压状态必须由 `pointerdown` 开始，并由 `pointerup`、`pointerleave` 或 `pointercancel` 结束。

## 验收清单

- 截取无交互画面，确认所有默认按钮四周亮度均匀。
- hover 任意按钮，确认主光和邻近受光立即出现。
- 移出按钮，确认所有光场状态立即清除。
- 按住中心按钮，确认上下左右近邻强于四个斜角邻居。
- 按住边角按钮，确认不存在布局外的虚构邻居。
- 确认邻居亮面都朝向当前主光按钮。
- 确认按钮间隙始终保持页面背景色。
- 使用键盘按住数字键，确认 `keydown`/`keyup` 生命周期一致。
- 在触摸视口验证松手后不会遗留 hover 状态。
